Đoạn code nên thuộc: search có debounce

type SearchState<T> =
  | { status: 'idle' | 'loading'; data: T[] }
  | { status: 'success'; data: T[] }
  | { status: 'error'; data: T[]; error: unknown };

// `search` must be stable (wrap it in useCallback) or the effect re-runs every render
function useDebouncedSearch<T>(
  query: string,
  search: (q: string, signal: AbortSignal) => Promise<T[]>,
  delay = 300,
): SearchState<T> {
  const [state, setState] = useState<SearchState<T>>({ status: 'idle', data: [] });

  useEffect(() => {
    const q = query.trim();
    if (!q) {
      setState({ status: 'idle', data: [] });
      return;
    }
    const controller = new AbortController();
    const timer = setTimeout(async () => {
      setState(s => ({ status: 'loading', data: s.data }));
      try {
        const data = await search(q, controller.signal);
        if (!controller.signal.aborted) setState({ status: 'success', data });
      } catch (error) {
        if (!controller.signal.aborted) setState(s => ({ status: 'error', data: s.data, error }));
      }
    }, delay);
    // New keystroke or unmount: drop the pending call and ignore its response
    return () => {
      clearTimeout(timer);
      controller.abort();
    };
  }, [query, search, delay]);

  return state;
}

Đoạn code nên thuộc: infinite scroll + pull-to-refresh

type Page<T> = { items: T[]; next?: string };
type Mode = 'initial' | 'more' | 'refresh';

function useInfiniteList<T extends { id: string }>(fetchPage: (cursor?: string) => Promise<Page<T>>) {
  const [items, setItems] = useState<T[]>([]);
  const [cursor, setCursor] = useState<string>();
  const [hasMore, setHasMore] = useState(true);
  const [loading, setLoading] = useState<Mode | null>('initial');
  const [error, setError] = useState<unknown>();
  const inFlight = useRef(false); // onEndReached can fire several times in a row

  const load = useCallback(async (mode: Mode) => {
    if (inFlight.current || (mode === 'more' && !hasMore)) return;
    inFlight.current = true;
    setLoading(mode);
    setError(undefined);
    try {
      const page = await fetchPage(mode === 'more' ? cursor : undefined);
      setItems(prev => {
        const base = mode === 'more' ? prev : [];
        const seen = new Set(base.map(i => i.id));
        return [...base, ...page.items.filter(i => !seen.has(i.id))];
      });
      setCursor(page.next);
      setHasMore(Boolean(page.next));
    } catch (e) {
      setError(e); // keep the items already on screen
    } finally {
      inFlight.current = false;
      setLoading(null);
    }
  }, [cursor, hasMore, fetchPage]);

  useEffect(() => { load('initial'); }, []); // eslint-disable-line react-hooks/exhaustive-deps

  return { items, loading, error, loadMore: () => load('more'), refresh: () => load('refresh') };
}

// Usage
<FlatList
  data={items}
  keyExtractor={item => item.id}
  renderItem={renderItem}            // stable via useCallback, row wrapped in React.memo
  onEndReached={loadMore}
  onEndReachedThreshold={0.5}
  refreshing={loading === 'refresh'}
  onRefresh={refresh}
  ListFooterComponent={loading === 'more' ? <ActivityIndicator /> : null}
  ListEmptyComponent={loading === 'initial' ? <ActivityIndicator /> : error ? <RetryButton onPress={refresh} /> : <Text>Chưa có dữ liệu</Text>}
/>

Xem đáp án (8 lỗi)Show the answer (8 bugs)
  • Stale closure: users trong effect là giá trị cũ. Dùng setUsers(prev => [...prev, ...d]).
  • Không xử lý lỗi: thiếu .catch và không kiểm tra r.ok.
  • Race condition: không hủy request; trang về sai thứ tự sẽ chèn sai. Dùng AbortController trong cleanup.
  • onEndReached gọi nhiều lần: không có cờ đang tải và không biết đã hết trang, nên tải trùng trang.
  • Rò rỉ listener: subscription AppState không được remove() trong cleanup.
  • setPage(1) không reset danh sách: dữ liệu trang 1 bị nối thêm vào cuối. Nếu page đang là 1 thì effect còn không chạy lại.
  • Key sai chỗ: key trong renderItem bị bỏ qua và lại là index. Dùng keyExtractor={u => u.id}.
  • Re-render thừa: renderItem và onPress tạo mới mỗi lần render nên Row có memo cũng vô ích; useState([]) không có type sẽ thành never[] trong TS.
  • Stale closure: users inside the effect is an old value. Use setUsers(prev => [...prev, ...d]).
  • No error handling: there's no .catch, and r.ok is never checked.
  • Race condition: requests are never cancelled, so pages that come back out of order land in the wrong place. Abort them in the cleanup.
  • onEndReached fires repeatedly: there's no in-flight flag and no notion of the last page, so the same page gets loaded twice.
  • Leaked listener: the AppState subscription is never remove()d in a cleanup.
  • setPage(1) doesn't reset the list: page 1 gets appended to the end again. And if page is already 1, the effect doesn't even re-run.
  • Key in the wrong place: React ignores a key returned from renderItem, and it's the index anyway. Use keyExtractor={u => u.id}.
  • Wasted re-renders: renderItem and onPress are recreated on every render, so memoizing Row achieves nothing. Also, useState([]) without a type is inferred as never[] in TypeScript.

class SearchPage extends StatefulWidget {
  const SearchPage({super.key, required this.search});
  final Future<List<Repo>> Function(String query) search;

  @override
  State<SearchPage> createState() => _SearchPageState();
}

class _SearchPageState extends State<SearchPage> {
  Timer? _debounce;
  int _requestId = 0;
  bool _loading = false;
  Object? _error;
  List<Repo> _results = const [];

  void _onChanged(String text) {
    _debounce?.cancel();
    _debounce = Timer(const Duration(milliseconds: 300), () => _run(text.trim()));
  }

  Future<void> _run(String query) async {
    final id = ++_requestId; // only the latest request may update the UI
    if (query.isEmpty) {
      setState(() {
        _results = const [];
        _error = null;
        _loading = false;
      });
      return;
    }
    setState(() {
      _loading = true;
      _error = null;
    });
    try {
      final results = await widget.search(query);
      if (!mounted || id != _requestId) return;
      setState(() {
        _results = results;
        _loading = false;
      });
    } catch (e) {
      if (!mounted || id != _requestId) return;
      setState(() {
        _error = e;
        _loading = false;
      });
    }
  }

  @override
  void dispose() {
    _debounce?.cancel();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        TextField(
          onChanged: _onChanged,
          decoration: const InputDecoration(hintText: 'Search repositories'),
        ),
        if (_loading) const LinearProgressIndicator(),
        if (_error != null)
          Text('Something went wrong', style: TextStyle(color: Theme.of(context).colorScheme.error)),
        Expanded(
          child: ListView.builder(
            itemCount: _results.length,
            itemBuilder: (context, i) => ListTile(
              key: ValueKey(_results[i].id),
              title: Text(_results[i].name),
            ),
          ),
        ),
      ],
    );
  }
}

class PageResult<T> {
  const PageResult(this.items, this.next);
  final List<T> items;
  final String? next; // null means there are no more pages
}

class _FeedPageState extends State<FeedPage> {
  final _scroll = ScrollController();
  final _items = <Post>[];
  final _ids = <String>{};
  String? _cursor;
  bool _hasMore = true;
  bool _loading = false; // guards against duplicate page requests
  Object? _error;

  @override
  void initState() {
    super.initState();
    _scroll.addListener(() {
      if (_scroll.position.extentAfter < 500) _loadMore();
    });
    // setState is not allowed inside initState, so start after the first frame
    WidgetsBinding.instance.addPostFrameCallback((_) => _loadMore());
  }

  Future<void> _loadMore() async {
    if (_loading || !_hasMore) return;
    setState(() {
      _loading = true;
      _error = null;
    });
    try {
      final page = await widget.fetchPage(_cursor);
      if (!mounted) return;
      setState(() {
        for (final p in page.items) {
          if (_ids.add(p.id)) _items.add(p); // dedupe by id
        }
        _cursor = page.next;
        _hasMore = page.next != null;
      });
    } catch (e) {
      if (mounted) setState(() => _error = e); // keep what is already on screen
    } finally {
      if (mounted) setState(() => _loading = false);
    }
  }

  Future<void> _refresh() async {
    if (_loading) return; // don't race a page that is still loading
    _loading = true;
    try {
      final page = await widget.fetchPage(null);
      if (!mounted) return;
      setState(() {
        _items
          ..clear()
          ..addAll(page.items);
        _ids
          ..clear()
          ..addAll(page.items.map((p) => p.id));
        _cursor = page.next;
        _hasMore = page.next != null;
        _error = null;
      });
    } catch (e) {
      if (mounted) setState(() => _error = e); // the old list stays visible
    } finally {
      _loading = false;
    }
  }

  @override
  void dispose() {
    _scroll.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    if (_items.isEmpty && _loading) return const Center(child: CircularProgressIndicator());
    if (_items.isEmpty && _error != null) {
      return Center(child: TextButton(onPressed: _loadMore, child: const Text('Retry')));
    }
    return RefreshIndicator(
      onRefresh: _refresh,
      child: ListView.builder(
        controller: _scroll,
        physics: const AlwaysScrollableScrollPhysics(),
        itemCount: _items.length + (_hasMore || _error != null ? 1 : 0),
        itemBuilder: (context, i) {
          if (i == _items.length) {
            return _error != null
                ? TextButton(onPressed: _loadMore, child: const Text('Retry'))
                : const Padding(
                    padding: EdgeInsets.all(16),
                    child: Center(child: CircularProgressIndicator()),
                  );
          }
          final post = _items[i];
          return PostTile(key: ValueKey(post.id), post: post);
        },
      ),
    );
  }
}

Xem đáp án (8 lỗi)Show the answer (8 bugs)
  • Dùng state và context sau await: không kiểm tra mounted; widget đã dispose thì setState và ScaffoldMessenger sẽ lỗi.
  • Không xử lý lỗi: không try/catch, không kiểm tra statusCode; jsonDecode payload lớn chạy trên UI isolate.
  • Tải trang trùng: listener ở đáy cuộn gọi nhiều lần liên tiếp, page++ nhảy trang; không có cờ đang tải và không biết hết trang.
  • Rò rỉ subscription: stream connectivity không được cancel trong dispose, và mỗi lần đổi mạng lại nối thêm trang hiện tại vào danh sách.
  • Không dispose ScrollController.
  • Unbounded height: ListView nằm trong Column không có Expanded sẽ báo lỗi layout.
  • ListView(children:) build toàn bộ danh sách; dùng ListView.builder và Key theo id.
  • Type và chữ ký: List users là List<dynamic> không có model; void load() async không await được và lỗi bị nuốt, nên dùng Future<void>; thiếu const và super.key.
  • State and context used after an await: mounted is never checked, so setState and ScaffoldMessenger blow up if the widget has been disposed.
  • No error handling: no try/catch and no statusCode check, and jsonDecode runs on the UI isolate even for large payloads.
  • Duplicate page loads: the bottom-of-list listener fires several times in a row, so page++ skips pages. There's no in-flight flag and no notion of the last page.
  • Leaked subscription: the connectivity stream is never cancelled in dispose, and every network change appends the current page to the list again.
  • The ScrollController is never disposed.
  • Unbounded height: a ListView inside a Column without Expanded throws a layout error.
  • ListView(children:) builds the entire list up front. Use ListView.builder with keys based on id.
  • Types and signatures: List users is a List<dynamic> with no model; void load() async can't be awaited and swallows errors, so make it Future<void>; const and super.key are missing.

// app/transactions/page.tsx (Server Component)
import { Suspense } from 'react'
import { SearchBox } from './search-box'
import { verifySession } from '@/lib/dal'
import { searchTransactions } from '@/lib/transactions'

export default function Page(props: PageProps<'/transactions'>) {
  return (
    <main>
      <h1>Transactions</h1>
      {/* useSearchParams needs a Suspense boundary, or the route can't be prerendered */}
      <Suspense fallback={<input type="search" disabled aria-label="Search transactions" />}>
        <SearchBox />
      </Suspense>
      <Suspense fallback={<p>Loading transactions…</p>}>
        <Results searchParams={props.searchParams} />
      </Suspense>
    </main>
  )
}

async function Results({ searchParams }: Pick<PageProps<'/transactions'>, 'searchParams'>) {
  const { q } = await searchParams // a Promise since Next.js 15; sync access was removed in 16
  const query = typeof q === 'string' ? q.trim().slice(0, 100) : ''
  const { userId } = await verifySession() // reads cookies: runtime data, so it stays inside Suspense
  const items = await searchTransactions(userId, query)

  if (items.length === 0) return <p>No transactions match “{query}”.</p>
  return (
    <ul>
      {items.map((t) => (
        <li key={t.id}>
          {t.note}: {t.amount.toLocaleString('vi-VN')} ₫
        </li>
      ))}
    </ul>
  )
}

// lib/transactions.ts
import 'server-only'
import { cacheLife, cacheTag } from 'next/cache'
import { db } from '@/lib/db'

export async function searchTransactions(userId: string, query: string) {
  'use cache' // userId and query become part of the cache key
  cacheLife('minutes')
  cacheTag(`transactions:${userId}`) // the Server Action calls updateTag with this tag
  return db.transaction.findMany({
    where: { userId, note: { contains: query } },
    orderBy: { date: 'desc' },
    take: 50,
    select: { id: true, note: true, amount: true, date: true },
  })
}

// app/transactions/search-box.tsx
'use client'

import { useEffect, useRef, useState, useTransition } from 'react'
import { usePathname, useRouter, useSearchParams } from 'next/navigation'

export function SearchBox() {
  const router = useRouter()
  const pathname = usePathname()
  const searchParams = useSearchParams()
  const [text, setText] = useState(searchParams.get('q') ?? '')
  const [isPending, startTransition] = useTransition()
  const timer = useRef<ReturnType<typeof setTimeout>>(undefined)

  useEffect(() => () => clearTimeout(timer.current), []) // no timer firing after unmount

  function onChange(value: string) {
    setText(value) // the input stays responsive; only the URL update is debounced
    clearTimeout(timer.current)
    timer.current = setTimeout(() => {
      const params = new URLSearchParams(searchParams.toString()) // keep other filters
      const q = value.trim()
      if (q) params.set('q', q)
      else params.delete('q')
      params.delete('page') // a new query starts again from page 1
      const qs = params.toString()
      startTransition(() => {
        // replace, not push: one history entry per search, not per keystroke
        router.replace(qs ? `${pathname}?${qs}` : pathname, { scroll: false })
      })
    }, 300)
  }

  return (
    <div role="search">
      <label htmlFor="q">Search</label>
      <input id="q" type="search" value={text} onChange={(e) => onChange(e.target.value)} />
      <span aria-live="polite">{isPending ? 'Searching…' : ''}</span>
    </div>
  )
}

router.replace chạy trong transition nên React giữ kết quả cũ trên màn hình thay vì hiện lại fallback, và isPending báo đang tìm. Câu hỏi tiếp theo hay gặp: người dùng bấm Back thì ô input có cập nhật theo URL không (gợi ý: đồng bộ lại khi searchParams đổi, hoặc dùng key), và vì sao searchTransactions nhận userId làm tham số thay vì tự đọc cookie bên trong 'use cache'.

// app/transactions/actions.ts
'use server'

import { z } from 'zod'
import { updateTag } from 'next/cache'
import { verifySession } from '@/lib/dal'
import { db } from '@/lib/db'

const NewTransaction = z.object({
  amount: z.coerce.number().int().positive().max(1_000_000_000), // VND: whole numbers only
  note: z.string().trim().min(1, 'Note is required').max(200),
  categoryId: z.uuid(),
  date: z.iso.date(),
})

export type FormState = {
  ok: boolean
  message?: string
  fieldErrors?: Record<string, string[] | undefined>
  values?: Record<string, string>
}

export async function createTransaction(_prev: FormState, formData: FormData): Promise<FormState> {
  // 1. Authenticate inside the action: it's a public POST endpoint
  const { userId } = await verifySession()

  // 2. Validate: FormData is untrusted input. Pick fields explicitly.
  const raw = {
    amount: String(formData.get('amount') ?? ''),
    note: String(formData.get('note') ?? ''),
    categoryId: String(formData.get('categoryId') ?? ''),
    date: String(formData.get('date') ?? ''),
  }
  const parsed = NewTransaction.safeParse(raw)
  if (!parsed.success) {
    // Return the values: React resets the form after the action, so the UI refills them
    return { ok: false, fieldErrors: z.flattenError(parsed.error).fieldErrors, values: raw }
  }

  // 3. Authorize: the category must belong to this user (prevents IDOR)
  const category = await db.category.findFirst({
    where: { id: parsed.data.categoryId, userId },
    select: { id: true },
  })
  if (!category) return { ok: false, message: 'Category not found', values: raw }

  try {
    await db.transaction.create({
      data: { ...parsed.data, date: new Date(parsed.data.date), userId },
    })
  } catch {
    return { ok: false, message: 'Could not save. Please try again.', values: raw }
  }

  // 4. Read-your-own-writes: expire this user's cached list right away
  updateTag(`transactions:${userId}`)
  return { ok: true, message: 'Saved' }
}

Xem đáp án (8 lỗi)Show the answer (8 bugs)
  • Client Component async: 'use client' cùng async function không được hỗ trợ. Trang này nên là Server Component, fetch dữ liệu trên server rồi truyền xuống phần client nhỏ.
  • searchParams đọc đồng bộ: từ Next.js 15 searchParams là Promise, Next.js 16 bỏ hẳn truy cập đồng bộ; phải await (hoặc use() trong client), và prop cũng không có type.
  • useEffect không có dependency: chạy sau mỗi render, setItems lại gây render, thành vòng lặp gọi API vô tận; items trong closure bị cũ nên nối trùng dữ liệu; không kiểm tra res.ok, không hủy request cũ.
  • Secret ở client: process.env.API_SECRET không có tiền tố NEXT_PUBLIC_ nên là undefined trên trình duyệt; còn nếu có thì secret lộ trong bundle và trong query string (log, history).
  • Code server trong module client: import db vào file 'use client' kéo code DB vào bundle; Server Function không được khai báo trong Client Component, phải đặt trong file 'use server' và DAL có server-only.
  • Action không kiểm tra quyền: không xác thực, không kiểm tra giao dịch có thuộc user không (IDOR), không validate id, không revalidate nên UI vẫn hiện item đã xóa.
  • Index làm key: xóa hoặc nối thêm item khiến React gắn state sai phần tử; dùng t.id.
  • XSS: dangerouslySetInnerHTML với ghi chú do người dùng nhập; render thẳng {t.note} hoặc sanitize nếu thật sự cần HTML.
  • Async Client Component: 'use client' combined with an async function isn't supported. This page should be a Server Component that fetches on the server and passes data to a small client piece.
  • Synchronous searchParams: since Next.js 15 searchParams is a Promise, and Next.js 16 removed synchronous access entirely, so you have to await it (or use() it on the client). The prop isn't typed either.
  • useEffect with no dependency array: it runs after every render, setItems triggers another render, and you get an endless request loop. The items in the closure is stale, so data gets appended twice, and there's no res.ok check or cancellation of the previous request.
  • A secret on the client: process.env.API_SECRET has no NEXT_PUBLIC_ prefix, so it's undefined in the browser; and if it were exposed, the secret would leak through the bundle and the query string (logs, history).
  • Server code in a client module: importing db into a 'use client' file pulls database code into the bundle, and you can't define a Server Function inside a Client Component. It belongs in a 'use server' file backed by a server-only DAL.
  • No authorization in the action: no authentication, no check that the transaction belongs to the user (IDOR), no validation of id, and no revalidation, so the UI keeps showing the deleted item.
  • Index as key: deleting or appending items makes React attach state to the wrong element. Use t.id.
  • XSS: dangerouslySetInnerHTML with a user-supplied note. Render {t.note} directly, or sanitize it if you genuinely need HTML.

// Artifacts: lifecycle-viewmodel-ktx, lifecycle-runtime-compose (collectAsStateWithLifecycle),
// compose-foundation (TextFieldState), material3, hilt-lifecycle-viewmodel-compose (hiltViewModel)
data class Repo(val id: Long, val name: String, val stars: Int)

interface RepoRepository {
    suspend fun search(query: String): List<Repo> // main-safe (Retrofit suspend)
}

sealed interface SearchUiState {
    data object Idle : SearchUiState
    data object Loading : SearchUiState
    data class Success(val repos: List<Repo>) : SearchUiState
    data class Error(val message: String) : SearchUiState
}

@OptIn(FlowPreview::class, ExperimentalCoroutinesApi::class)
@HiltViewModel
class SearchViewModel @Inject constructor(
    private val repository: RepoRepository,
) : ViewModel() {

    // TextFieldState is a snapshot-backed state holder; the docs encourage keeping it in the ViewModel
    val queryState = TextFieldState()
    private val retryTrigger = MutableStateFlow(0)

    private val query: Flow<String> = snapshotFlow { queryState.text.toString().trim() }
        .debounce(300)
        .distinctUntilChanged()

    val uiState: StateFlow<SearchUiState> = combine(query, retryTrigger) { q, _ -> q }
        .flatMapLatest { q -> // a new query cancels the request still in flight
            if (q.isEmpty()) {
                flowOf(SearchUiState.Idle)
            } else {
                flow<SearchUiState> {
                    emit(SearchUiState.Loading)
                    emit(SearchUiState.Success(repository.search(q)))
                }.catch { e -> emit(SearchUiState.Error(e.message ?: "Something went wrong")) }
            }
        }
        .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), SearchUiState.Idle)

    fun retry() = retryTrigger.update { it + 1 }
}

@Composable
fun SearchRoute(viewModel: SearchViewModel = hiltViewModel()) {
    val uiState by viewModel.uiState.collectAsStateWithLifecycle()
    SearchScreen(queryState = viewModel.queryState, uiState = uiState, onRetry = viewModel::retry)
}

@Composable
fun SearchScreen(
    queryState: TextFieldState,
    uiState: SearchUiState,
    onRetry: () -> Unit,
    modifier: Modifier = Modifier,
) {
    Column(modifier.fillMaxSize()) {
        TextField(
            state = queryState,
            modifier = Modifier.fillMaxWidth().padding(16.dp),
            placeholder = { Text("Search repositories") },
            lineLimits = TextFieldLineLimits.SingleLine,
        )
        when (uiState) {
            SearchUiState.Idle -> Unit
            SearchUiState.Loading -> LinearProgressIndicator(Modifier.fillMaxWidth())
            is SearchUiState.Error -> Row(
                modifier = Modifier.padding(16.dp),
                verticalAlignment = Alignment.CenterVertically,
            ) {
                Text(uiState.message, Modifier.weight(1f), color = MaterialTheme.colorScheme.error)
                TextButton(onClick = onRetry) { Text("Retry") }
            }
            is SearchUiState.Success ->
                if (uiState.repos.isEmpty()) {
                    Text("No results", Modifier.padding(16.dp))
                } else {
                    LazyColumn(Modifier.weight(1f)) {
                        items(uiState.repos, key = { it.id }) { repo ->
                            ListItem(
                                headlineContent = { Text(repo.name) },
                                supportingContent = { Text("★ ${repo.stars}") },
                            )
                        }
                    }
                }
        }
    }
}

Đoạn code nên thuộc: infinite scroll + pull-to-refresh

data class Post(val id: Long, val title: String)
data class FeedPage(val items: List<Post>, val nextCursor: String?) // null means no more pages

interface FeedApi {
    suspend fun fetch(cursor: String?): FeedPage
}

data class FeedUiState(
    val items: List<Post> = emptyList(),
    val isRefreshing: Boolean = false,
    val isLoadingMore: Boolean = false,
    val endReached: Boolean = false,
    val error: String? = null,
)

@HiltViewModel
class FeedViewModel @Inject constructor(private val api: FeedApi) : ViewModel() {
    private val _state = MutableStateFlow(FeedUiState())
    val state: StateFlow<FeedUiState> = _state.asStateFlow()

    private var cursor: String? = null
    private var loadJob: Job? = null // only touched on the main thread

    init { refresh() }

    fun refresh() {
        loadJob?.cancel() // a refresh wins over a page that is still loading
        loadJob = viewModelScope.launch {
            _state.update { it.copy(isRefreshing = true, isLoadingMore = false, error = null) }
            try {
                val page = api.fetch(cursor = null)
                cursor = page.nextCursor
                _state.update {
                    it.copy(
                        items = page.items.distinctBy(Post::id),
                        isRefreshing = false,
                        endReached = page.nextCursor == null,
                    )
                }
            } catch (e: CancellationException) {
                throw e // never swallow cancellation
            } catch (e: Exception) {
                _state.update { it.copy(isRefreshing = false, error = e.message ?: "Couldn't refresh") }
            }
        }
    }

    fun loadMore() {
        if (loadJob?.isActive == true || _state.value.endReached) return // in-flight guard
        loadJob = viewModelScope.launch {
            _state.update { it.copy(isLoadingMore = true, error = null) }
            try {
                val page = api.fetch(cursor)
                cursor = page.nextCursor
                _state.update { s ->
                    val seen = s.items.mapTo(HashSet<Long>()) { it.id }
                    s.copy(
                        items = s.items + page.items.filter { seen.add(it.id) }, // dedupe by id
                        isLoadingMore = false,
                        endReached = page.nextCursor == null,
                    )
                }
            } catch (e: CancellationException) {
                throw e
            } catch (e: Exception) {
                _state.update { it.copy(isLoadingMore = false, error = e.message ?: "Couldn't load more") }
            }
        }
    }
}

@Composable
fun FeedRoute(viewModel: FeedViewModel = hiltViewModel()) {
    val state by viewModel.state.collectAsStateWithLifecycle()
    FeedScreen(state, onRefresh = viewModel::refresh, onLoadMore = viewModel::loadMore)
}

@Composable
fun FeedScreen(
    state: FeedUiState,
    onRefresh: () -> Unit,
    onLoadMore: () -> Unit,
    modifier: Modifier = Modifier,
) {
    val listState = rememberLazyListState()
    val currentOnLoadMore by rememberUpdatedState(onLoadMore)

    // Emits the item count while the user is within 5 items of the end, so it fires
    // again after each new page but not in a loop when a load fails
    LaunchedEffect(listState) {
        snapshotFlow {
            val info = listState.layoutInfo
            val last = info.visibleItemsInfo.lastOrNull()?.index ?: return@snapshotFlow -1
            if (last >= info.totalItemsCount - 5) info.totalItemsCount else -1
        }
            .distinctUntilChanged()
            .filter { it > 0 }
            .collect { currentOnLoadMore() }
    }

    PullToRefreshBox(
        isRefreshing = state.isRefreshing,
        onRefresh = onRefresh,
        modifier = modifier.fillMaxSize(),
    ) {
        LazyColumn(state = listState, modifier = Modifier.fillMaxSize()) {
            items(state.items, key = { it.id }, contentType = { "post" }) { post ->
                ListItem(headlineContent = { Text(post.title) })
            }
            if (state.isLoadingMore) {
                item(key = "loading", contentType = "footer") {
                    Box(Modifier.fillMaxWidth().padding(16.dp), contentAlignment = Alignment.Center) {
                        CircularProgressIndicator()
                    }
                }
            }
            state.error?.let { message ->
                item(key = "error", contentType = "footer") {
                    Row(Modifier.padding(16.dp), verticalAlignment = Alignment.CenterVertically) {
                        Text(message, Modifier.weight(1f))
                        TextButton(onClick = if (state.items.isEmpty()) onRefresh else onLoadMore) {
                            Text("Retry")
                        }
                    }
                }
            }
        }
    }
}

Không dùng runCatching ở đây vì nó nuốt CancellationException, khiến refresh không hủy được trang đang tải. Nếu đề cho dùng thư viện, nói được cách làm tương đương bằng Paging 3: Pager + cachedIn(viewModelScope), collectAsLazyPagingItems(), itemKey { it.id } và loadState.

Xem đáp án (8 lỗi)Show the answer (8 bugs)
  • GlobalScope: coroutine không bị hủy khi ViewModel bị clear, chạy trên Dispatchers.Default và sửa state từ thread nền. Dùng viewModelScope.launch.
  • Mutate list bên trong StateFlow: users.value.addAll(...) sửa cùng một instance nên StateFlow không phát (giá trị vẫn equals) và không thread-safe; thêm nữa MutableStateFlow / MutableSharedFlow public cho phép UI ghi vào. Dùng private val _users = MutableStateFlow<List<User>>(emptyList()), _users.update { it + new } và expose asStateFlow().
  • Leak Activity: ImageCache là singleton giữ this của Activity, sau mỗi lần xoay màn Activity cũ không được thu hồi. Chỉ giữ applicationContext.
  • I/O trên main thread: readText() trong onCreate chặn UI (StrictMode sẽ báo, nguy cơ ANR) và ném FileNotFoundException ở lần chạy đầu khi file chưa có, làm app crash. Đọc trong coroutine với Dispatchers.IO (hoặc DataStore) và xử lý trường hợp chưa có.
  • Collect không theo lifecycle: lifecycleScope.launch { collect } trong onCreate vẫn chạy khi app ở nền và hiện Toast khi không ai nhìn; collectAsState() cũng vậy. Dùng repeatOnLifecycle(STARTED) và collectAsStateWithLifecycle(); với message, theo guidance nên quy về UI state thay vì SharedFlow không replay (mất message khi chưa có collector).
  • Side effect trong composition: viewModel.load() chạy lại ở mỗi recomposition, gõ một ký tự là gọi API và nối thêm dữ liệu trùng. Gọi trong init của ViewModel hoặc LaunchedEffect(Unit).
  • State mất khi xoay màn: remember { mutableStateOf(initialQuery) } mất query khi Activity tạo lại hoặc process death. Dùng rememberSaveable, hoặc đưa query vào ViewModel (TextFieldState / SavedStateHandle).
  • LazyColumn không có key và lọc trong composition: expanded bám theo vị trí, nên khi lọc thay đổi trạng thái mở rộng bị gán nhầm item; filter chạy lại mỗi recomposition tạo list mới. Thêm key = { it.id } và đưa việc lọc vào ViewModel (hoặc remember(users, query)).
  • GlobalScope: the coroutine isn't cancelled when the ViewModel is cleared, runs on Dispatchers.Default, and mutates state from a background thread. Use viewModelScope.launch.
  • Mutating a list inside a StateFlow: users.value.addAll(...) changes the same instance, so the StateFlow never emits (the value is still equals) and it isn't thread-safe; on top of that, the public MutableStateFlow and MutableSharedFlow let the UI write to them. Use private val _users = MutableStateFlow<List<User>>(emptyList()), _users.update { it + new }, and expose asStateFlow().
  • Leaked Activity: ImageCache is a singleton holding the Activity's this, so every rotation leaves the old Activity uncollectable. Only keep the applicationContext.
  • I/O on the main thread: readText() in onCreate blocks the UI (StrictMode will flag it, and it's an ANR risk) and throws FileNotFoundException on first launch when the file doesn't exist yet, crashing the app. Read it in a coroutine on Dispatchers.IO, or use DataStore, and handle the missing case.
  • Lifecycle-unaware collection: lifecycleScope.launch { collect } in onCreate keeps running in the background and shows toasts nobody sees, and collectAsState() has the same problem. Use repeatOnLifecycle(STARTED) and collectAsStateWithLifecycle(). For messages, the guidance is to reduce them to UI state rather than a SharedFlow with no replay, which drops messages when nothing is collecting.
  • Side effect in composition: viewModel.load() runs on every recomposition, so typing one character fires the API again and appends duplicates. Call it from the ViewModel's init or from LaunchedEffect(Unit).
  • State lost on rotation: remember { mutableStateOf(initialQuery) } loses the query when the Activity is recreated or the process dies. Use rememberSaveable, or move the query into the ViewModel with TextFieldState or SavedStateHandle.
  • No keys in the LazyColumn, and filtering during composition: expanded sticks to a position, so when the filter changes the expanded state lands on the wrong item, and filter builds a new list on every recomposition. Add key = { it.id } and move filtering into the ViewModel, or at least remember(users, query).
